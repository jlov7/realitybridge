# RealityBridge next-increment protocol (frozen before new outcomes)

23 September 2026. Owner: AI-assisted local study. Baseline source: `bcb55139991da376ed90b323935a3c8d2cedac67`, branch `feat/next-increment`. This protocol is written before any new reference experiment in this increment. Historical receipts and the measured pre-fix source remain immutable. All new outputs belong in this increment's `rb` directory or new repository paths. No publication or outside contact is authorized.

## Common boundaries and accounting

Six operations only: create/get/edit issue, create label, add/remove issue label. One synthetic Gitea API on owned loopback Docker state. New reference jobs run serially. Every attempt records exact source, image digest and architecture, inputs, action and state traces, request count, elapsed time, failures and unknowns. A transport or setup failure is `undetermined`. Source and protocol hashes precede outcome inspection. We do not claim an independent reviewer from another AI agent. A second version is transfer evidence on exposed cases. The historical ordinary comparison (12 cases, 229 requests, two divergent instances detected by both comparators) remains separate.

## A: normalization challenge

Plant paired raw states with equal visible label names/colors but changed membership row identity, duplicate rows, swapped issue assignments and ordinary generated-ID drift. Test whether a subsequent in-scope action or separately observed API state distinguishes them. Only introduce a creation-order logical identity map if the behavior is observable and the map has a pairing source; never compare raw IDs directly across runs. Record controls proving ordinary ID drift does not trigger divergence. If the six-operation interface cannot distinguish rows, retain an explicit blind spot and do not call it a behavioral defect.

## B: blind outside oracle packet

Export raw action responses, raw post-action state, the six-operation contract and relevant API schema excerpts. The reviewer-facing capsule excludes comparator verdicts, expected labels and prior adjudications. Keep a separate answer key and manifest with content hashes. Supply an independent classification form (`agree`, `diverge`, `unsupported`, `undetermined`), rationale, evidence fields, and discrepancy docket. No outside-human result exists unless an actual outside reviewer returns a classification; packet preparation alone is partial.

## C: prospective matched-effort ordinary workflow

Use the same six-operation action grammar and frozen defect families for two workflows. The ordinary arm gets a strong stateful contract comparator with post-step full-state readback, pagination and cardinality checks; the RealityBridge arm gets its existing oracle and case tools. Both can author sequences within a fixed per-arm budget. Freeze families and candidate traces before outcomes, never call previously exposed E/N cases holdout. Count setup, case and oracle authoring time, implementation edits, reference resets/requests, computation, unknowns and adjudication. Primary result: unique independently adjudicated defect instances per total effort, with all attempts and unknowns. If independent authorship/adjudication is unavailable, run an explicitly AI-authored feasibility comparison and report independent-adjudication and superiority conclusions `unavailable`. The null of equal or better ordinary discovery is valid.

## D: downstream decisions

Freeze task sources, state goals, candidate policies, stop rules and utility before reference outcomes. Include routine tasks and a separately flagged exposed-defect positive control. Run every task/policy cell on simulator and reference. Decompose ranking change due to task shift from ranking change due to simulator error. Record censored cells, requests and task provenance. Do not count the positive control as novel discovery; a zero simulator-induced regret remains a valid result.

## E: repair generalization

Freeze separately designed defect families and train/known-regression/unseen sequence splits before a repair attempt. The worker sees only allowed staged source and train counterexamples through the existing sandbox; evaluation cases and oracle logic stay inaccessible. For each family record the proposed patch, target outcome, old regression results, unseen outcomes, failed attempts, requests and time. An unrun worker or inaccessible sandbox means repair success is `unavailable`, not assumed from a hand-written fix. Shared AI design is not independent replication.

## F: bounded version transfer

Inspect cached images first. Select one official second Gitea build by exact architecture-specific digest and verify all six OpenAPI paths/methods against that build before cases. Run the frozen exposed set with the same simulator source and label version behavior separately from simulator defects. Stop at an image/API/permission mismatch and retain the compatibility matrix; do not substitute a tag for a digest or silently drop a case. This is one additional build, not a general compatibility claim.

## Resource bounds and stop conditions

A: at most eight synthetic planted pairs and three live targeted sequences, at most 80 measured API requests. B: existing raw receipts only, zero new reference calls. C: at most 12 cases per arm, 320 calls per arm; if equal-effort authorship cannot be measured, no superiority claim. D: at most six tasks by three policies, 300 calls; all cells retained. E: at most three defect families, one repair attempt each, 300 calls; setup and sandbox failures retained. F: one extra image and at most 12 exposed cases, 320 calls. Stop any phase on ownership, digest, custody, budget, or reference-health failure. No fallback that changes the study after observing favorable outcomes. Full suite runs after implementation; local test pass cannot substitute for a live reference outcome or human review.
