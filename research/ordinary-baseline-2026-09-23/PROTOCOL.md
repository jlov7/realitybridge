# Fresh ordinary stateful testing comparison — frozen protocol

Status: protocol and cases proposed before any new reference observation. The 2026-09-22 development/evaluation cases and 30 exposed requalification cases are regression material only. This study is an AI-authored comparison, pending separate AI review of the oracle, normalization, and cases before execution. That review is not independent human replication.

## Scope and question

One pinned Gitea 1.24.7 ARM64 digest, one six-operation grammar, the exact measured pre-fix emulator source, and twelve new synthetic sequences `N01`–`N12` in `experiments/ordinary_baseline_cases.py`. Ask whether a competent ordinary stateful contract comparator, given the same action responses and complete state observations, detects fewer true differences or incurs more false alarms than RealityBridge's current four-way comparison. A null or adverse result is publishable. No model-agent or population claim follows.

## Pre-observation commitments

1. Freeze this protocol, case module, ordinary comparator, runner and study-critical source hashes in a committed manifest before any live run. Export the exact reviewed commit with `experiments/prepare_ordinary_study.py`, then materialize the measured emulator baseline from that archive. The live receipt records both the reviewed origin commit and actual materialized study commit/tree and checks every frozen file hash before observing data. Parent AI reviewer inspects the frozen protocol, case choices, and both comparison paths. Record challenges and any amendments *before* data. No substitution, dropping or reordering of cases after results. If amendments follow observations, call them exploratory and keep the first attempt.
2. Use the exact measured baseline emulator bytes `experiments/research_baseline_emulator_19b2b47.py` (SHA-256 `61b81d7b4f5c97a1116855fbb93c422d772d9342c5503c1f84b7bd659f3c02ac`) in a materialized clean tree. The historical receipt remains untouched. Record actual source/tree, image digest and architecture.
3. Use the existing `run_case` path and reference meter once per case. Each case starts with `soft_reset`, simulator reset, initial full-state check, then response and full declared state after every action. Feed both methods the *same* captured raw responses/errors/states. Neither comparator makes reference calls. Record all reset, action, readback and recheck requests. Hard cap 320 HTTP requests for all twelve cases; cap exhaustion is censored and cannot be counted as agreement or negative discovery.
4. Static worst-case admission is 12 × (8 reset/seed + 2 initial readback) + 32 actions × (3 action + 2 readback) = 280 HTTP requests, plus seven initial seed requests; the 320 cap leaves 33 for pagination growth, and cap exhaustion remains censored. The ordinary comparator is written independently of the RealityBridge projection and oracle modules. It asserts response category/status and declared issue/label/attachment cardinality and rows, maps identity by issue number and label name, ignores only generated ids/URLs and exact timestamp values while checking timestamp presence, parseability, relation and close/open semantics. It preserves duplicate rows and attachment multiplicity. It distinguishes missing, denied, validation and transport errors; malformed data is unknown. It produces the same four categories: agree, diverge, unsupported, undetermined. It may use all snapshot rows, including pagination-derived rows.
5. The instrument comparator is the existing response projection plus full-state oracle. Collect per-step outputs and explicit difference reasons. A case discovery is the first determinate divergence, not every later symptom. A false alarm is a method's divergence that an adjudicated raw trace finds to be semantically equivalent. A miss is a reference-confirmed difference the method labels agree. Reviewer disagreements and unresolved cases remain visible as disputed/unknown. Neither method's output is ground truth by itself.
6. Compare full per-case outcomes and per-step coverage, request count, actions, resets, readbacks, human/AI implementation effort, discoveries, false alarms, misses and unknowns jointly. Both methods share the same reference request cost by design. This comparison does not measure case-discovery efficiency or equal authoring effort. Record implementation effort descriptively where available and otherwise as unknown; do not invent time or cost. Comparator runtime costs are separate. Report per-case raw trace links and every attempted action, including setup failures. No favorable subset, post-hoc cost reweighting, or conversion of unknown into agreement.

## Stopping and interpretation

Stop on the predeclared request cap, reference health/architecture violation, non-owned Compose resource, or custody/hash mismatch. Retain partial raw trace and failure. A good ordinary baseline matching or exceeding the instrument on discoveries and false alarms falsifies the strong incremental-comparator-advantage claim on this shared workload. Neither method is ground truth; adjudicate raw traces independently, including cases both miss. A difference in either direction on twelve authored cases remains local evidence, not a general superiority claim. Follow-up cases are exploratory unless a new protocol is frozen first.
