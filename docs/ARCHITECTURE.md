# Architecture and design decisions

RealityBridge tests whether a bounded simulator matches a reference on **observed transitions**. The motivating use is choosing or debugging behavior against a cheaper simulator before consulting a reference service. This repository measured a synthetic Gitea issue-and-label workload and a scripted policy-selection exercise. It did not measure a deployed agent or a production decision system.

## One paired case

A case begins with reset and an initial state check, then applies the same sequence of six permitted operations to a pinned, loopback-only Gitea instance and a local `Emulator`. `experiments/research_completion.py` drives the finite study; `src/reality_bridge/reference.py` meters API calls and exports Gitea's declared state, including paginated rows. `src/reality_bridge/emulator.py` has its own transition logic and state export. After each action, `prospective_comparison.py` validates and projects both responses; `state_oracle.py` separately validates and compares the full declared issue, label, and issue-label state. The evaluator does not import emulator transition logic.

The [operation contract](../contracts/operations.yaml) fixes the six-action grammar. The [observation contract](../contracts/observation.yaml) documents meaningful IDs, semantic fields, time relations, error categories, and exclusions. Sorting order-insensitive rows while retaining multiplicity detects duplicate effects; issue number remains observable. The implementation does not claim arbitrary logical-ID reconciliation, exact timestamp equality, concurrency, or any operation outside that contract. A wrong or incomplete observation contract can still hide a defect.

A response and a state comparison have separate channels. A determinate difference produces `diverge` with a reason and evidence. Valid matching observations produce `agree`. Malformed, uncertain, or unavailable observations produce `undetermined`; a simulator operation outside scope produces `unsupported`. Neither latter outcome is counted as agreement. For example, a transport-uncertain result cannot show that two effects match. Error categories such as permission denial, not found, and validation conflict stay distinct.

## Why observe full state?

The measured **E06** counterexample shows the purpose. Two same-name label creations left Gitea with distinct registry rows and the original issue membership, while the baseline simulator's name-keyed table replaced a row. The action responses matched. A response-only comparator would miss the state difference; the independent state export found it. The exact pre-fix emulator is retained at `experiments/research_baseline_emulator_19b2b47.py`. The current `src/` emulator contains later fixes. [Frozen results](research-completion-2026-09-22/RESULTS.md) distinguish the two.

The full-state minimizer in `src/reality_bridge/shrink.py` takes a selected action and a response or state defect signature. It tries shorter prefixes and interior deletions using fresh paired runs. A candidate sequence replaces the original only if the **same selected signature** is reproduced determinately. Unknown, absence, and exhausted budget do not become a successful reduction. Reference resets, readbacks, probes, and final recheck are charged to the cap. The exposed [E06 engineering receipt](../artifacts/engineering-minimization-2026-09-23/e06-evidence-bound.json) retained both necessary label creations after four probes and a final recheck, using 81 requests. This is a regression example, not new holdout evidence.

## Study boundaries

The 2026-09-22 protocol froze cases, source and cost rules before its prospective evaluation. Discovery arms had an actual 180-request cap each, with completed cases admitted at shared cutoffs. This matters because a method cannot gain apparent coverage by ignoring setup, failed calls, or readbacks. The 16 new evaluation cases yielded 13 agreements and three divergences; the scripted policy selection showed no simulator-induced regret on its six evaluation task instances. [The result](research-completion-2026-09-22/RESULTS.md) gives the full decomposition and limits.

The later [ordinary stateful comparator protocol](../research/ordinary-baseline-2026-09-23/PROTOCOL.md) used the *same captured traces* for both comparators, so reference-request cost was shared. Its first attempt failed during setup after 17 requests, before any N01 action. [Amendment 1](../research/ordinary-baseline-2026-09-23/AMENDMENT-1.md) applied an already known label-color repair, retained the failed receipt, and ran the same twelve case instances. Both methods found the same two divergent instances in 229 requests. Two ordinary-comparator unknowns exposed a timestamp-validation weakness in the former instrument oracle. AI raw-trace cross-review found no extra in-scope RealityBridge discovery. The amended outcome, setup failure, frozen source archives, and later repaired-source recheck are separate records in the [evidence index](EVIDENCE-INDEX.md).

The project therefore supports a reproducible, bounded comparison method and concrete counterexamples. It does not establish a general agent platform, superior discovery over competent ordinary testing, independent human validation, or Gitea equivalence beyond the declared observations. See [limitations](../research/LIMITATIONS.md) and [current status](../STATUS.md).
